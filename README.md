# Windows AI applications through a pinned VPN

Диагностика повторного запуска ChatGPT и ошибки sandbox: [TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).

Скрипты для Claude Desktop, нативного Claude Code, Codex Desktop и Codex CLI на Windows. Выбранный профиль v2rayN копируется в отдельный локальный прокси без прямого резервного выхода. Перед защищённым запуском проверяются профиль, TUN, правила блокировки и реальное HTTPS-соединение.

**Статус: разработка и локальная проверка. Установка целиком на чистом компьютере пока не подтверждена.** Перечень доказанных проверок и открытых задач: [VALIDATION.md](docs/VALIDATION.md).

## Что настраивается

- Автозапуск v2rayN через задачу Windows с повышенными правами. Claude и Codex автоматически не запускаются.
- Существующие MSIX StartupTask выбранных приложений отключаются адресно, с резервированием и восстановлением при удалении. Пакет Codex может отображать свою задачу как «ChatGPT». Общая настройка восстановления приложений Windows не изменяется; её влияние проверяется отдельно после входа.
- Ярлыки `Claude VPN` / `Codex VPN` на рабочем столе и в меню «Пуск».
- Функции `claude` / `codex` в новых окнах PowerShell; отдельные команды `claude-vpn` / `codex-vpn` для CMD.
- Блокировка исходящих соединений защищённых исполняемых файлов через физические интерфейсы и TUN. Им остаётся локальный прокси, закреплённый за выбранным сервером.
- Отдельная блокировка известных альтернативных портов прокси через Windows Filtering Platform, для IPv4 и IPv6.
- Отдельный Node.js для загрузчика Codex CLI. Общий Node.js, внешние git, curl, PowerShell и Python не ограничиваются.
- Для Codex включается `NODE_USE_ENV_PROXY=1` в окружении запуска: встроенный Node.js WebSocket-клиент также должен использовать закреплённый HTTP-прокси. Изменение требует полного перезапуска приложения.
- Локальные секреты хранятся вне репозитория, с доступом только текущему пользователю, SYSTEM и администраторам.

Cloudflare WARP на сервере допускается. Изменение внешнего IP WARP не считается ошибкой. Закрепляется сервер и его учётные данные, а не IP, который показывает сайт проверки.

## До установки

1. Нужны Windows 11 24H2 или новее, Windows PowerShell 5.1 x64/ARM64, работающий Windows Firewall и возможность подтвердить UAC тем же Windows-пользователем. Ограничение версии нужно для удаления неподписанной AppID-политики без перезагрузки: [документация Microsoft](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/deployment/disable-appcontrol-policies).
2. Установите v2rayN, настройте нужный сервер, запустите v2rayN с правами администратора и включите TUN. Выберите профиль, который нужно закрепить.
3. Установите нужные AI-приложения. По умолчанию установщик ожидает все четыре: пакетные Claude Desktop и Codex Desktop, нативный Claude Code и официальный Codex CLI.
4. Полностью закройте выбранные AI-приложения и их встроенные процессы. Установщик сам их не завершает.

Автоматическое восстановление из сохранённой базы поддерживает VLESS/TCP/REALITY. Для других вариантов нужен существующий Xray core JSON через `-CoreConfigPath`; он сверяется с выбранной записью базы. Неоднозначные и неподдерживаемые конфигурации отклоняются.

## Одна команда

После публикации и завершения проверок репозитория выполните в обычном PowerShell:

```powershell
& ([scriptblock]::Create((Invoke-RestMethod 'https://raw.githubusercontent.com/mpodreshetnikov/work-environment-setup/main/bootstrap.ps1')))
```

Bootstrap получает конкретный commit из `main`, скачивает его архив в закрытый временный каталог и запрашивает UAC. Локальные ключи VPN никуда не отправляются. Для установки проверенного commit укажите `-Commit <полный SHA>`; для сохранения обхода проблем GPU добавьте `-DisableGpu`. Также поддерживаются `-Apps`, `-V2rayRoot`, `-CoreConfigPath`, `-TunInterfaceAlias`, `-ProxyPort` и `-AdditionalDeniedProxyPorts`.

Команда не устанавливает сами v2rayN, Claude, Codex или Node.js. Это настройка уже установленных программ. При нескольких подходящих путях или интерфейсах используйте явные параметры из локальной копии:

```powershell
# В повышенном Windows PowerShell 5.1 из каталога репозитория:
.\install.ps1 -V2rayRoot 'C:\Programs\v2rayN' -TunInterfaceAlias 'singbox_tun' -DisableGpu

# Только выбранные приложения:
.\install.ps1 -Apps ClaudeDesktop,ClaudeCode -TunInterfaceAlias 'singbox_tun'

# Только просмотр, без изменения системы:
.\plan.ps1
```

`C:\Programs\v2rayN` и `singbox_tun` в примере замените своими значениями. Установщик пытается найти их автоматически. Занятый порт по умолчанию `20080` требует явного `-ProxyPort`. Дополнительные локальные прокси укажите в `-AdditionalDeniedProxyPorts`.

Повторная установка проверяет уже установленную конфигурацию. Она не заменяет закреплённый профиль и не добавляет повторные правила. Старый прототип `ClaudeVpnGuard` обнаруживается отдельно: автоматическая миграция пока не реализована, установка поверх него отклоняется.

## После установки

Откройте новое окно PowerShell. Запускайте приложения через VPN-ярлыки либо команды `claude` и `codex`. В CMD используйте `claude-vpn` / `codex-vpn`; новый пользовательский PATH появляется в новых сеансах оболочки.

```powershell
$setup = Join-Path $env:LOCALAPPDATA 'WorkEnvironmentSetup\AiVpn'
& "$setup\verify.ps1"
```

Проверка подтверждает текущее состояние прокси, интерфейса и правил. Отправка настоящего сообщения, обрыв сети и вход после перезагрузки требуют отдельной проверки по [инструкции](docs/VALIDATION.md).

Обновление AI-приложения, смена Node.js или архитектуры может потребовать обновления списка защищённых файлов. При этом защищённый запуск отклоняется. Закройте приложения и выполните из повышенного Windows PowerShell:

```powershell
& "$env:LOCALAPPDATA\WorkEnvironmentSetup\AiVpn\repair.ps1"
```

Repair обновляет обнаруженные пути, загрузчик и правила. Существующий приватный конфиг VPN сохраняется. Для смены сервера восстановление не используется: отдельная процедура repin пока не реализована. Во время обслуживания выбранные приложения должны оставаться закрытыми.

## Удаление и восстановление

Из повышенного Windows PowerShell, после закрытия выбранных приложений:

```powershell
& "$env:LOCALAPPDATA\WorkEnvironmentSetup\AiVpn\uninstall.ps1"
```

Удаляются только правила, политики, фильтры, задача и интеграция этого установщика. Предыдущие профили PowerShell и совпадавший автозапуск v2rayN восстанавливаются из локального журнала. Последующие изменения пользователя в профилях сохраняются, удаляется управляемый блок. Сами приложения и v2rayN остаются установленными.

По умолчанию приватный каталог сохраняется для восстановления. Для удаления его содержимого добавьте `-PurgePrivateState`. При ошибке отката каталог удалять нельзя: в нём находятся идентификаторы правил и резервные копии.

## Границы защиты

- Проверка запуска действует на созданные ярлыки и функции оболочки. Прямой запуск EXE, штатная запись MSIX в «Пуск» или исходный `codex.cmd` из CMD не перехватываются. Сетевые ограничения установленных исполняемых файлов продолжают действовать, но собственная ошибка VPN при таком запуске не гарантируется.
- Блокируются обнаруженные файлы и узкие AppID-шаблоны встроенных процессов. Для нового пути после обновления требуется repair. Копирование исполняемого файла в произвольный другой каталог не входит в модель защиты.
- Блокируются известные альтернативные порты v2rayN и дополнительные явно заданные порты. Произвольный новый локальный relay не считается изолированным. Остальной loopback нужен приложениям для IPC и локальных интеграций.
- Внешние инструменты намеренно работают как обычно. Прокси-переменные, унаследованные ими от агента, могут направить их через прокси; принудительных сетевых ограничений на них нет.
- Уже работающий закреплённый Xray может продолжить соединение с выбранным сервером после выключения TUN или смены профиля GUI. Следующий защищённый запуск будет отклонён. Это не watchdog, мгновенно завершающий текущие приложения.
- Нет защиты от администратора или вредоносного кода того же пользователя, меняющего установку и правила.

## Проверки разработчика

```powershell
# Из обычного Windows PowerShell 5.1, без изменений сетевых правил:
.\tests\Run-Tests.ps1

# Реальные установленные приложения и отдельный временный прокси:
.\tests\Run-Tests.ps1 -Live -TunInterfaceAlias 'singbox_tun'

# Изолированные правила для временной копии curl; запросит UAC:
.\tests\Invoke-NetworkProtectionTest.ps1

# Включая изолированную проверку задачи, ярлыков и профилей:
.\tests\Invoke-NetworkProtectionTest.ps1 -Integration

# Также проверить блокировку настоящего IPv4 HTTPS (потребуется интернет):
.\tests\Invoke-NetworkProtectionTest.ps1 -Integration -DirectHttpsCheck
```

Сетевая проверка использует отдельный файл, отдельную AppID-политику и собственные фильтры; затем проверяет откат и восстановление соединения. Она не выключает VPN и не перезапускает рабочие AI-приложения.

Техническая основа: [AppID tagging и Windows Firewall](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules), [условия WFP по приложению и пользователю](https://learn.microsoft.com/en-us/windows/win32/fwp/permitting-and-blocking-applications-and-users), [права чтения объектов WFP](https://learn.microsoft.com/en-us/windows/win32/fwp/access-control).
