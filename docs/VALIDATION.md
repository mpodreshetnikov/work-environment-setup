# Проверки и оставшиеся задачи

Результаты ниже относятся к локальной разработке. Они не заменяют проверку чистой установки на другом компьютере. Код целиком ещё не применялся к рабочим приложениям этим переносимым установщиком.

## Проверено

- Чтение выбранного профиля из сохранённых GUI JSON и SQLite без изменения базы. Отсутствие временного `binConfigs/config.json` не блокирует поддерживаемый импорт.
- Проверки неоднозначных серверов, несовпадающей идентичности, понижения безопасности, неподдерживаемого транспорта и ошибочного JSON без вывода его приватного содержимого.
- Разрешение реальных путей через junction и определение архитектуры PE без запуска файла.
- Приватные ACL, атомарная запись JSON, Unicode, отказ от чужого владельца и небезопасных разрешений.
- Подготовка отдельного Xray с одним outbound и валидация его конфигурации.
- Реальное HTTPS-соединение через временный закреплённый прокси, повторное использование собственного listener, отказ при несовпадении профиля и отсутствии TUN.
- Нативный CLI bridge: кавычки, пустые аргументы, Unicode, короткие опции, stdin/stdout, коды возврата, отсутствие изменения прокси-переменных родительского процесса.
- Обнаружение четырёх установленных дистрибутивов и подготовка отдельного Node.js для Codex CLI. Изменённый bootstrap и backend вне утверждённых путей отклоняются.
- Отдельный повышенный тест постоянных WFP-фильтров: заблокирована временная копия curl, обычный системный curl доступен; проверены AppID-tag и SID пользователя. Проверка из обычного PowerShell читает реальные фильтры. Удаление правил, фильтров и политики подтверждено; соединение временного файла восстановилось.
- С `-DirectHttpsCheck` подтверждён отказ настоящего исходящего IPv4 HTTPS у временного защищённого файла: до правил запрос успешен, после установки код curl 7, после отката снова успешен. Системный curl продолжал работать при включённых правилах.
- Создание и удаление настоящей повышенной задачи без её запуска. Ярлыки, профили и Run-ключ проверены в изолированных каталогах/ветке реестра: восстановлены исходные байты, сохранены последующие правки пользователя, проверены отсутствующие профили и повторный откат. Настоящие профили пользователя и PATH этот тест не менял.
- Отключение MSIX StartupTask выбранного приложения: проверены исходные состояния 0/1/2/3, отсутствующий State, повторный откат, сохранение последующей правки пользователя и отказ при включении политикой администратора. На рабочем Codex его включённая задача «ChatGPT» переведена из State=2 в State=1 с резервной копией; следующий вход в Windows ещё требует проверки.
- В окружение VPN-запуска Codex добавлен `NODE_USE_ENV_PROXY=1`. Локальный WebSocket-клиент приложения явно проверяет этот флаг перед созданием proxy-aware Agent. После полного перезапуска рабочего Codex все наблюдавшиеся установленные TCP-соединения защищённых процессов шли через закреплённый loopback-прокси, включая соединение основного процесса, которое ранее обходило его.
- На рабочем прототипе включена строгая защита Codex: 39 правил Windows Firewall и 152 постоянных WFP-фильтра. Новая временная копия curl в области AppID Codex успешно выполнила HTTPS через закреплённый прокси; прямой HTTPS через TUN и известный альтернативный прокси получили код 7. Обычный системный curl выполнил запрос успешно. Это проверка сетевых ограничений, а не всей матрицы отказов или переносимого установщика.
- После включения строгой защиты настоящий Codex CLI через VPN guard выполнил отдельный ephemeral-запрос из временного каталога: ответ `OK`, код завершения 0. Запуск использовал read-only sandbox и игнорировал пользовательский config.toml. Это проверка CLI; ответ Codex Desktop после включения правил проверяется отдельно.

- [x] Проверить задачу, ярлыки, существующие/отсутствующие профили, резервирование Run и повторный откат через `Invoke-NetworkProtectionTest.ps1 -Integration`.
- [ ] Проверить пользовательский PATH и целиком интеграцию на изолированной учётной записи или VM.
- [ ] Подтвердить повторный откат сетевой защиты по одному и тому же журналу после удаления объектов; дополнительный сценарий добавлен в тест.
- [ ] Проверить установку, повторный запуск, repair и uninstall целиком на чистой Windows.
- [ ] Проверить bootstrap из опубликованного конкретного commit.
- [ ] Проверить настоящий запрос Claude Desktop, Claude Code, Codex Desktop и Codex CLI через закреплённый прокси.
- [ ] Проверить обрыв сервера, остановку локального прокси, выключение TUN, смену профиля, физический выход IPv4/IPv6 и отсутствие резервного маршрута у защищённых процессов.
- [ ] Проверить вход в Windows после перезагрузки: сначала повышенный v2rayN, приложения запускаются только вручную.
- [ ] Решить оставшиеся ограничения обычных способов запуска; текущая реализация гарантирует собственную проверку только для управляемых способов.

- [x] Локально проверены исходники и существовавшая история Git: личные ID профиля, адрес сервера, UUID и ключ REALITY отсутствуют. Перед публикацией проверку повторить для финального commit.

В рабочем старом прототипе область cache Codex уже сужена до встроенного Node.js и artifact RPC daemon. Хеш обновлённой активной AppID-политики сверен с локальным бинарником. Это исправление не означает завершения миграции на переносимый установщик.

## Ручная проверка после установки

1. Выполнить `verify.ps1`. Не считать только наличие TUN или совпадение внешнего IP доказательством.
2. Через VPN-ярлыки отправить по одному реальному сообщению в оба desktop-приложения, затем проверить обе CLI.
3. Сохранить результат, полностью закрыть приложения. Выключить TUN и проверить отказ защищённого запуска с понятной ошибкой. Вернуть TUN.
4. Сменить профиль GUI и проверить отказ нового запуска. Вернуть закреплённый профиль.
5. На тестовом компьютере остановить закреплённый прокси во время запроса: защищённый процесс не должен перейти на прямой интерфейс или другой известный локальный прокси. Восстановить прокси, повторить запрос.
6. Проверить непосредственный запуск исходных файлов отдельно. Открытие окна само по себе не доказывает возможность отправки запроса; отсутствие своего диалога VPN при прямом запуске сейчас ожидаемо.
7. Проверить, что обычные git, curl, PowerShell и Python продолжают работать вне ограничений приложений.
8. Перезагрузить Windows. Проверить повышение v2rayN без постоянного UAC на входе, отсутствие автозапуска AI-приложений и успешный ручной VPN-запуск после готовности TUN.

При провале проверки сохранить локальный журнал. Не удалять его до успешного отката. Не публиковать приватные JSON, базу профилей, XML с локальными путями или конфигурацию прокси в issue.
